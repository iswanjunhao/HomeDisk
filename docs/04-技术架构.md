## 1. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│  浏览器（手机 / 平板 / 电脑，同一局域网）                      │
│   public/index.html + style.css + app.js  （纯前端，无构建）   │
└───────────────────────────┬────────────────────────────────┘
                             │  HTTP / JSON  ( :8080 )
┌───────────────────────────┴────────────────────────────────┐
│  Node.js + Express  (server.js)                              │
│                                                             │
│  中间件层：                                                   │
│   · cookieParser       解析会话                              │
│   · json(2mb)          解析请求体                            │
│   · lanOnly 校验       仅放行局域网 IP                        │
│                                                             │
│  路由层 (src/routes)：                                        │
│   /api/files   list / usage / download / download-zip / thumb │
│   /api/upload  init / chunk / done / cancel  （分片上传）      │
│   /api/manage  mkdir / rename / move / delete / tree         │
│   /api/search  search / categories                           │
│   /api/auth    login / logout                                │
│                                                             │
│  基础库 (src/lib)：                                           │
│   pathGuard（路径安全） config（配置） auth（认证）            │
│   indexer（索引）   classifier（分类） format（格式化）        │
└───────────────────────────┬────────────────────────────────┘
                             │  fs
                   ┌─────────┴──────────┐
                   │  共享磁盘（root）    │
                   │  /mnt/homedisk      │
                   │  或 Windows D:\      │
                   └─────────────────────┘
```

前端是**纯静态文件**，不经过任何打包工具；后端是**单进程 Express 服务**，无数据库（配置落盘 JSON、索引落盘 JSON、缩略图落盘 WebP）。

## 2. 核心数据流

### 2.1 目录浏览
`GET /api/list?path=/a/b` → `pathGuard.resolveSafe` 校验路径合法 → `fs.readdir` → 并发 `stat` → `indexer.sortEntries` 排序 → 返回 `[{name, path, isDir, size, mtime, type}]`。

### 2.2 分片上传
1. `POST /api/upload/init`：校验目录、文件名清洗、大小闸门（>1GB 且非管理员 → 401 并要求密码）、预留 `xxx.hcpart` 与最终名。
2. `POST /api/upload/chunk?uploadId=...`：逐片以原始字节追加写入 `.hcpart`（每片 ≤20MB）。
3. `POST /api/upload/done`：校验字节数一致 → `rename` 落定 → 失效索引。

### 2.3 搜索
`GET /api/search?q=...&path=...`：
- 索引已建立 → 内存匹配（毫秒级）；
- 索引未就绪 → 实时遍历兜底（结果可能截断，前端提示）。

## 4. 安全模型

| 防护 | 实现 |
|---|---|
| 路径穿越 | `pathGuard.resolveSafe`：`path.posix.normalize` 折叠 `..` → `path.resolve` 拼接 → `fs.realpathSync` 解析符号链接 → 前缀比对，任一环节失败即拒绝 |
| 符号链接逃逸 | `realpath` 后再比对前缀，软链接指向共享盘外则 403 |
| 恶意文件名 | `safeName` 剔除控制字符、`/` `\`、开头连续点，挡掉 Windows 保留名 |
| 局域网边界 | `auth.isPrivateIp` 仅放行私有网段；`lanOnly` 可关 |
| 认证 | scrypt 哈希存储；httpOnly Cookie 会话；`timingSafeEqual` 防时序攻击 |
| 暴力破解 | 同一 IP 5 次/分钟失败 → 锁定 10 分钟 |
| 根目录保护 | 不允许删除 / 重命名 / 移动共享盘根目录本身 |

## 5. 性能与容量

- **索引**：后台全量扫描，`MAX_ENTRIES=300000` 上限，扫描 >8 分钟自动收敛；每 30 分钟增量刷新；缓存落盘 `data/index-cache.json`。
- **上传**：分片 20MB/片，未完成 `.hcpart` 24 小时后清理；同盘 `rename` 落定，避免拷贝大文件。
- **下载**：ZIP 流式打包不落盘；单文件 Range 续传。
- **缩略图**：WebP 缓存（`data/thumbs/`），以 `md5(abs|mtime)` 为键，文件更新自动失效。

## 7. 测试覆盖（开发期已验证）

- 路径穿越 / URL 编码 / 符号链接逃逸 → 全部拦截
- 未登录删除 / 重命名 / 移动 → 401，前端弹密码框
- 上传超限（>1GB，未登录）→ 401「需要管理员密码」
- 同名文件 / 恶意文件名 `../../tmp/x` → 自动重命名 / 清洗，未逃出共享盘
- 中文名下载 + 断点续传 + ZIP 中文名 → 正常
- 管理员重命名 / 移动 / 删非空文件夹 → 成功；把文件夹移入自身 → 拒绝；删根目录 → 拒绝
