# 家庭局域网私有网盘（HomeCloud）需求文档

> 版本：v1.0 ｜ 日期：2026-10-26 ｜ 状态：**待确认**

---

## 一、目标与背景

### 1.1 一句话目标

把本机那块 **1T 硬盘** 变成一个"家庭私有云盘"：只要设备连上家里 WiFi（局域网），用浏览器打开一个地址，就能像用百度网盘一样**查看、上传、下载**这块盘上的文件，无需公网、无需云服务商、无需安装客户端。

### 1.2 现状环境（已实测）

| 项 | 实测值 |
|---|---|
| 操作系统 | Ubuntu 26.04.1 LTS，内核 7.0.0-38-generic |
| 共享目标盘 | `/dev/sda2`，**931.5G，NTFS**，当前**未挂载** |
| 分区表线索 | `sda1` = 16M（Microsoft Reserved），`sda2` = 931.5G NTFS → 疑似 Windows 系统/数据盘 |
| 系统盘 | `/dev/nvme0n1p2`（233G ext4，挂载于 `/`） |
| 局域网 IP | `192.168.1.14` |
| 可用运行时 | Node.js 22.22.2、Python 3.13.12、npm；**无 Docker、无 Go、无 git** |
| NTFS 驱动 | 内核 `ntfs3` 模块存在，`ntfs-3g`（FUSE）已安装 |
| 网络 | npm registry 可达；github 页面在沙箱内未连通（不影响自研） |

### 1.3 不在本次范围内

- 公网访问 / 内网穿透 / HTTPS 域名（明确不做，避免暴露到互联网）
- 多用户账号体系（只做"访客 + 管理员密码"两级）
- 文件同步客户端、离线缓存、版本历史、回收站（v2 再考虑）
- 转码、在线解压、Office 在线编辑

## 三、功能需求清单

### R1 目录浏览
- 面包屑路径导航，支持逐级返回与点击跳转
- **网格视图**（图标/缩略图）与**列表视图**（名称/大小/修改时间）一键切换
- 排序：按名称、大小、修改时间、类型；文件夹恒置顶
- 显示共享目录容量 / 已用 / 剩余（顶部容量条）

### R2 文件下载
- 单文件下载（支持断点续传 Range 请求，便于大文件/视频拖动）
- **多选文件/文件夹 → 打包成 ZIP 下载**（服务端流式打包，不落盘临时文件）
- 中文文件名正确编码（UTF-8，兼容 Windows 解压不乱码）

### R3 文件上传
- 点击选择文件（多选）
- **拖拽上传**（桌面端拖文件到网页）
- **移动端直接从相册选择 / 调用摄像头拍照上传**（`<input capture>`）
- **文件夹上传**（webkitdirectory，桌面端）
- 上传进度条、支持取消
- 大文件分片上传（默认单文件 ≤ 2G，分片 8MB，失败自动重试）
- 同名文件策略：**自动重命名**（`xxx (1).txt`），不静默覆盖

### R4 搜索
- 文件名模糊匹配，不区分大小写
- 范围可切换：**当前目录及子目录** / **全盘**
- 结果上限 500 条，显示所在路径，点击直达所在文件夹
- 后台增量索引 + 定时刷新，避免每次全盘遍历卡顿

### R5 文件分类
顶部/侧边分类导航，按扩展名自动归类：

| 分类 | 典型扩展名 |
|---|---|
| 图片 | jpg/jpeg/png/gif/webp/bmp/heic/svg/avif |
| 视频 | mp4/mkv/avi/mov/rmvb/flv/webm/m2ts/ts |
| 音频 | mp3/flac/wav/aac/ogg/m4a/ape |
| 文档 | pdf/doc/docx/xls/xlsx/ppt/pptx/txt/md/csv/epub |
| 压缩包 | zip/rar/7z/tar/gz/bz2/iso |
| 其他 | 上述之外的全部 |

- 分类可叠加"当前目录 / 全盘"范围
- 分类页支持排序（大小、时间）

### R6 在线预览（不下载直接看）
- 图片：缩略图 + 点击大图、左右切换、缩放
- 视频：HTML5 播放器（mp4/webm/mkv 若浏览器不支持则提示下载）
- 音频：内嵌播放器
- 文本 / 代码 / Markdown：内容直接展示（≤ 2MB）
- PDF：浏览器内嵌预览

### R7 权限模型

**两级角色：**

| 操作 | 访客（免登录） | 管理员（密码） |
|---|:--:|:--:|
| 浏览目录、查看文件 | ✅ | ✅ |
| 下载（单文件 / ZIP 打包） | ✅ | ✅ |
| 在线预览 | ✅ | ✅ |
| 搜索、分类筛选 | ✅ | ✅ |
| 上传文件 | ✅ | ✅ |
| 新建文件夹 | ✅ | ✅ |
| 重命名 / 移动 | ❌ | ✅ |
| 删除（单条 / 批量） | ❌ | ✅ |

- 管理员密码通过配置文件设置（首次启动时若未设置，强制在终端/网页设置一次）
- 登录有效期 8 小时，可手动退出；登录状态存 httpOnly Cookie
- 密码错误限流：同一 IP 5 次/分钟后锁定 10 分钟（防暴力破解）
- 未登录时点击受限操作 → 弹出密码框 → 输对后立即执行，**不打断操作流程**
- 配置项 `GUEST_UPLOAD`（默认 `true`），可一键关闭访客上传，改为"访客只读"

### R8 UI / 交互
- 中文界面，无英文术语堆砌
- 浅色为主，自动跟随系统深色模式
- 移动端优先：底部大号上传按钮、触控友好的多选、手势返回
- 空状态、加载态、错误提示齐全
- 顶部常驻搜索框 + 分类 Tab

### R9 系统级
- **开机自启动**：systemd 服务 `homecloud.service`
- **磁盘自动挂载**：`/etc/fstab` 挂载 `/dev/sda2` → `/mnt/homedisk`，带 `nofail` 防开机卡死
- 日志文件 + 基本访问记录（谁在什么时候上传/删除了什么）

## 四、非功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| N1 | **路径穿越防护** | 所有路径经 `realpath` 解析后必须仍在根目录内；`..`、符号链接、URL 编码绕过一律拒绝 |
| N2 | **仅局域网** | 服务不监听公网接口；文档明确禁止端口映射/内网穿透；可选"仅允许 192.168.x.x 网段"白名单 |
| N3 | **性能** | 单目录 ≤ 2000 条目时列表响应 < 500ms；索引常驻内存，增量更新 |
| N4 | **资源占用** | 空闲内存 < 120MB，CPU 接近 0 |
| N5 | **健壮性** | 磁盘未挂载时网页给出明确中文提示（"共享目录不可访问"），而非白屏/500 |
| N6 | **文件名兼容** | 支持中文、空格、emoji、超长文件名；Windows/macOS 解压不乱码 |
| N7 | **可维护性** | 依赖 ≤ 5 个 npm 包，代码注释中文，配置文件集中一处 |

## 五、技术选型对比（重要结论）

| 方案 | 维护状态 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **File Browser** | ❌ **2026-08-31 已归档停维护** | 轻量、单二进制 | 官方声明 2 类漏洞永不修复（命令执行、JWT 无法吊销/登出无效） | **排除** |
| **FileBrowser Quantum** | ✅ 活跃 | 索引搜索强、多数据源 | Go 单二进制，改动中文 UI/分类需重建前端（本机无 Go） | 备选 |
| **copyparty** | ✅ 活跃，47k star | 功能极强：续传/WebDAV/FTP/SMB/去重 | 界面**最密集**、配置靠手写文本、**无管理面板** → 不满足"UI 简单明了" | 备选 |
| **Nextcloud / Seafile** | ✅ 活跃 | 全家桶 | 需 LNMP/Docker，**本机无 Docker**，1T 盘场景过重 | 排除 |
| **AList / Filestash** | ✅ 活跃 | 多存储后端 | 面向云存储聚合，本地单盘场景多余；Filestash 免费版限 3 用户 | 排除 |
| **🎯 自研 Node.js 服务** | — | UI/权限/中文完全可控；约 2000 行代码；依赖极少；本机已有 Node 22 | 需自行实现，功能不如 copyparty 全面 | **推荐** |

**选择自研的理由**：需求非常聚焦（局域网单盘 + 简洁中文 UI + 两级权限），开源方案要么已停维护有安全隐患，要么 UI/配置复杂与"简单明了"直接冲突，要么过重。自研约 2000 行即可 100% 命中需求，且后续想加功能随时能改。

## 六、技术设计概要

### 6.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js 22.22.2 | 本机已有 |
| 后端 | Express 4 | 路由与静态资源 |
| 上传 | Multer + 自研分片合并 | 支持大文件 |
| 打包下载 | archiver | 流式 ZIP，不落盘 |
| 前端 | **原生 HTML/CSS/JS 单页** | 不引入 React/Vue 构建链，保持简单可维护；**所有资源本地化，不依赖任何 CDN**（局域网可能无外网） |
| 认证 | Cookie + 服务端 Session | 密码用 `scrypt` 哈希比对 |
| 索引 | 内存索引 + JSON 落盘缓存 | 后台增量扫描，定时持久化 |
| 部署 | systemd 服务 + fstab 自动挂载 | 开机即用 |

**依赖清单（仅 5 个）**：`express`、`multer`、`archiver`、`cookie-parser`、`mime-types`

### 6.2 目录结构

```
/mnt/homedisk/                  ← 1T NTFS 共享目录挂载点（fstab 自动挂载）

/opt/homecloud/                 ← 程序安装目录
├── server.js                   ← 入口
├── src/
│   ├── routes/                 ← API 路由（list/download/upload/search/admin...）
│   ├── lib/
│   │   ├── pathGuard.js        ← 路径安全校验（最重要）
│   │   ├── auth.js             ← 密码 & session
│   │   ├── indexer.js          ← 后台索引 & 搜索
│   │   └── classifier.js       ← 文件分类
│   └── public/                 ← 前端静态资源（index.html / app.js / style.css）
├── data/
│   ├── config.json             ← 配置（端口、根目录、管理员密码哈希、访客上传开关）
│   └── index-cache.json        ← 搜索索引缓存
└── logs/
```

### 6.3 核心 API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/list?path=&sort=&order=` | 访客 | 目录列表 |
| GET | `/api/search?q=&scope=&type=` | 访客 | 搜索 |
| GET | `/api/download?path=` | 访客 | 单文件下载（支持 Range） |
| POST | `/api/download-zip` | 访客 | 批量打包下载 |
| POST | `/api/upload?path=` | 访客* | 上传（multipart / 分片） |
| POST | `/api/mkdir` | 访客* | 新建文件夹 |
| POST | `/api/rename` | **管理员** | 重命名 |
| POST | `/api/move` | **管理员** | 移动 |
| POST | `/api/delete` | **管理员** | 删除（支持回收站模式） |
| POST | `/api/login` / `/api/logout` | — | 管理员登录/登出 |
| GET | `/api/usage` | 访客 | 共享目录容量 |
| GET | `/api/thumb?path=` | 访客 | 图片缩略图（带缓存） |

\* 可通过 `GUEST_UPLOAD=false` 关闭

### 6.4 磁盘挂载方案

```
# /etc/fstab 追加（UUID 待实测获取）
UUID=<sda2的UUID>  /mnt/homedisk  ntfs3  defaults,nofail,uid=1000,gid=1000,umask=022,iocharset=utf8  0  0
```

- 优先用内核 `ntfs3`（性能好）；若出现写入异常，降级为 `ntfs-3g`（更保守）
- `nofail` 保证盘不在时系统也能正常开机
- 服务启动时检测挂载点，未挂载则在网页明确提示

### 6.5 ⚠️ 需你确认的风险点

**该盘疑似 Windows 系统盘**（存在 16M 的 Microsoft Reserved 分区）。若确实是 Windows 系统盘，存在两个必须处理的问题：

1. **Windows 快速启动 / 休眠**会导致 Linux 只能以只读挂载（否则可能损坏 NTFS）。需要在 Windows 中关闭"快速启动"，或在 Linux 侧强制挂载。
2. 往 Windows 系统盘写文件本身有风险（可能误改系统文件）。

**建议方案（三选一，需你决定）：**
- **A. 全盘读写**：确认这块盘只是数据盘（无 Windows 系统）→ 直接读写共享
- **B. 全盘只读 + 独立上传区**：系统盘内容只读浏览，上传的文件写入该盘下一个固定目录（如 `/影音共享/`）→ 最安全
- **C. 全盘只读**：只允许查看和下载，不允许任何上传
